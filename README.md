# Автотесты для REST API Яндекс.Диска

![Python](https://img.shields.io/badge/python-3.9+-blue.svg)
![Pytest](https://img.shields.io/badge/pytest-9.0+-orange.svg)
![Requests](https://img.shields.io/badge/requests-2.34+-green.svg)

Проект автоматизированного тестирования REST API Яндекс.Диска, разработанный на Python с использованием Pytest и Requests.

В рамках проекта реализован набор тестов для проверки корректности работы API, обработки ошибок, валидации параметров запросов и соответствия структуры ответов документации сервиса. Тесты охватывают как позитивные пользовательские сценарии, так и негативные проверки, направленные на оценку устойчивости API к некорректным данным.

Проект выполнен в рамках отбора на стажировку **«Инженер по автоматизации тестирования в Финтех» (Яндекс)**.

# О проекте

Проект представляет собой набор автоматизированных тестов для REST API Яндекс.Диска.

Основные задачи проекта:

* проверка корректности работы REST API;
* тестирование позитивных и негативных сценариев;
* проверка обработки ошибок;
* проверка обязательных полей ответов;
* тестирование асинхронных операций;
* автоматическая подготовка и очистка тестовых данных;
* демонстрация практик проектирования поддерживаемых автотестов.

Особое внимание уделено качеству тестового покрытия и применению техник тест-дизайна.

## Архитектурные решения

### API-клиент как отдельный слой

Взаимодействие с API инкапсулировано в классе `YandexClient`.

Преимущества:

* отсутствие дублирования кода;
* централизованное управление запросами;
* удобство масштабирования проекта.

### Session-based подход

Для выполнения запросов используется `requests.Session()`.

Преимущества:

* переиспользование TCP-соединений;
* уменьшение накладных расходов;
* ускорение выполнения тестов.

### Разделение позитивных и негативных сценариев

Тесты разделены на две независимые группы:

```text
tests/positive
tests/negative
```

Такой подход улучшает читаемость и упрощает поддержку проекта.

### Автоматическая очистка данных

Фикстуры используют конструкцию `yield`, что гарантирует удаление тестовых объектов после выполнения тестов.

### Гибкая работа с параметрами

Методы клиента поддерживают передачу параметров через `**kwargs`, что позволяет легко адаптироваться к изменениям API.

# Конфигурация

## Получение OAuth-токена

Для запуска тестов необходимо использовать тестовый токен из Полигона Яндекс.Диска.

STR:

1. Перейти на страницу Полигона Яндекс.Диска.
2. Нажать кнопку **Получить OAuth-токен**.
3. Выполнить авторизацию.
4. Скопировать полученный токен.
5. Указать токен в файле `config.py`.

#  Запуск тестов

Перед запуском тестов важно убедиться, что диск пустой. Для этого можно выполнить скрипт. При необходимость с помощью этой же команды можно вызвать удаление ресурсов.
```bash
pytest tests/delete.py
```

## Все тесты

```bash
pytest tests/ -v
```

## Только позитивные сценарии

```bash
pytest tests/positive/ -v
```

## Только негативные сценарии

```bash
pytest tests/negative/ -v
```

## Запуск по маркерам

```bash
pytest -m positive -v

pytest -m negative -v
```

## Короткий traceback

```bash
pytest tests/ -v --tb=short
```

## Остановка после первой ошибки

```bash
pytest tests/ -v -x
```

#  Структура тестов

## Позитивные сценарии

Проверяют корректную работу API при валидных входных данных.

Примеры:

* создание папок;
* загрузка файлов;
* копирование ресурсов;
* публикация файлов;
* получение информации о ресурсе;
* получение информации о диске
* удаление ресурса

## Негативные сценарии

Проверяют обработку ошибок и защиту API от некорректных запросов.

Примеры:

* отсутствие обязательных параметров;
* несуществующие пути;
* невалидные типы данных;
* отрицательные значения параметров;
* ошибки авторизации;
* дублирование ресурсов.

# Фикстуры

Для подготовки и очистки тестовых данных используются фикстуры Pytest.

Основные задачи фикстур:

* создание тестовых директорий;
* создание файлов;
* удаление временных ресурсов;
* инициализация API-клиента.

# Техники тест-дизайна

| Техника                  | Применение                             |
| ------------------------ | -------------------------------------- |
| Contract Testing         | Проверка структуры ответов API         |
| Классы эквивалентности   | path, media_type, sort                 |
| Граничные значения       | limit, offset                          |
| Pairwise Testing         | Комбинации параметров запросов         |
| State Transition Testing | Проверка последовательности операций   |
| Error Guessing           | Проверка типичных ошибок пользователей |
| Negative Testing         | Проверка невалидных данных             |
| CRUD Testing             | Полный жизненный цикл ресурса          |
